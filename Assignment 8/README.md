# E-Commerce Order Analytics System

This mini-project simulates a real (but messy)
e-commerce dataset, cleans it, loads it into a SQL database, and
produces business reports — all built with Python and SQL.

**Skills practiced:** Python (pandas, sqlite3, functions), SQL (joins,
subqueries, CTEs, window functions), and general data-cleaning /
problem-solving.

---

## 1. Project Overview

This project is split into 5 parts, all built locally with Python and
SQLite:

| Part | What it does |
|------|---------------|
| Part 1 | Generates 4 raw CSV files with realistic, intentionally messy data |
| Part 2 | Cleans the data, validates emails, checks referential integrity |
| Part 3 | Loads cleaned data into SQLite and runs 16 SQL queries (basic → advanced) |
| Part 4 | A command-line tool that generates daily/weekly/monthly summary reports |
| Part 5 | Edge-case tests that check how the pipeline handles bad data |

## 3. Execution Order

Run everything from inside the `scripts/` folder, in this order:

```bash
# Part 1: generate the raw, messy CSV files
python3 generate_customers.py
python3 generate_products.py
python3 generate_orders.py
python3 generate_order_items.py

# Part 2: clean the data and produce a data quality report
python3 clean_data.py

# Part 3: load the cleaned data into a SQLite database
python3 load_sqlite.py

# Part 4: run the interactive command-line report tool
python3 reports.py

# Part 5: run the edge case tests
python3 tests.py
```

**Notes:**
- Files must be generated in this exact order because later scripts
  depend on the IDs created by earlier ones (for example, orders.csv
  needs customer_id values that already exist in customers.csv).
- Running any script again will simply overwrite its output file(s),
  so the whole pipeline is safe to re-run from scratch at any time.
- `reports.py` will ask you for a report type (daily/weekly/monthly)
  and a start/end date. The dataset covers dates roughly between
  mid-2024 and mid-2026, so try a range inside that window, for
  example `2025-01-01` to `2025-01-31`.

## 4. What Each Part Produces

### Part 1 — Data Generation
Creates 4 CSV files in `data/raw/`, each with 500+ rows and these
intentional issues:
- `orders.csv`: ~5% of rows have a missing (NULL/empty) `customer_id`;
  some rows use the wrong date format `DD-MM-YYYY` instead of
  `YYYY-MM-DD HH:MM:SS`.
- `order_items.csv`: ~3% of rows have negative `quantity` (returns); a
  small number of rows intentionally reference an `order_id` that does
  not exist, so Part 2's referential integrity check has something
  real to find.
- `products.csv`: some `product_name` values have extra spaces and/or
  random letter casing.
- `customers.csv`: ~2% of `email` values are invalid (missing `@` or
  missing a domain).

### Part 2 — Data Cleaning
`clean_data.py` contains 4 functions:
- `clean_orders()` — fixes both date formats into one consistent
  format, and replaces missing `customer_id` values with the text
  `"UNKNOWN"` so they're easy to spot and filter later.
- `clean_products()` — trims extra spaces and converts names to Title
  Case.
- `validate_emails()` — returns a list of `customer_id`s with invalid
  emails.
- `check_referential_integrity()` — returns a list of `item_id`s whose
  `order_id` does not exist in the orders table.

Running this script saves cleaned CSVs to `data/cleaned/` and writes
a full report to `reports/data_quality_report.txt`.

### Part 3 — SQL Analysis
`load_sqlite.py` loads the cleaned CSVs into `database/ecommerce.db`
(tables: `customers`, `products`, `orders`, `order_items`) and adds a
few indexes for performance.

The `sql/` folder has all 16 required queries, grouped by difficulty:
- **Basic:** revenue per category, top 10 customers, month-wise order
  counts.
- **Intermediate:** customers never delivered to, over-returned
  products, return rate per category.
- **Advanced:** running totals, `DENSE_RANK`, `LAG`/`LEAD` gap
  analysis, multi-level CTEs, `NTILE` quartiles, year-over-year
  growth, `FIRST_VALUE`/`LAST_VALUE`, cumulative revenue distribution,
  cohort retention analysis, and a self-join "frequently bought
  together" query.

### Part 4 — Python + SQL Integration
`reports.py` is an interactive command-line tool. It asks for a
report type and a date range, then prints total orders, total
revenue, unique customers, the top 3 products, and a percentage
comparison against the previous period of the same length.

### Part 5 — Edge Case Handling
`tests.py` has 4 plain Python test functions (no external testing
library needed) that check:
1. An `order_items` row pointing to a non-existent `order_id`.
2. A `discount_percent` greater than 100.
3. A `quantity` of exactly 0.
4. An `order_date` set in the future.

Run `python3 tests.py` to see each test's result printed to the
console.
